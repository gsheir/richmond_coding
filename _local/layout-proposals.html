Layout Proposals Design Exploration

Richmond HC Coding App — UI layout options inspired by NLE (non-linear editing) software conventions.
Created: 4 June 2026 · For review only, no code changes have been made.

Terminology note. In NLE/DAW software (Premiere Pro, DaVinci Resolve, Logic Pro), the resizable, titled regions are called panels. Within a workspace, panels are grouped into frames (the drag-target containers). A set of panel arrangements is saved as a workspace. This document uses panel throughout.

1 – Current Layout Audit

The existing layout stacks four layers vertically inside a right-of-sidebar content area:

  1. Top bar – clock display + Undo / Save / Export / More menu
  2. Match details card – date, home team, away team (full width, always visible)
  3. Middle row – code window (fixed 720 px) + analytics panel (flex-1)
  4. Bottom panel – event log / timeline (resizable, collapsible)

Current friction points

  • Left sidebar (240 px) never collapses during coding – wastes horizontal space
  • Match details card always takes full-width real estate, even though it rarely changes
  • Clock at 3 xl is dominant but the transport controls beside it are small
  • Analytics panel is always visible even though it is read-only during a live game
  • Active-phase indicator is buried inside the collapsible event log header
  • Title bar is 48 px tall but carries almost no content
  • Cards have rounded corners + backdrop blur – appropriate for a dashboard, but creates visual gaps in a tiled editor layout
  • Undo / Save / Export mixed in with clock controls – conceptually different actions

What's working well

  • Resizable event log height already exists
  • Log / Timeline toggle is intuitive
  • Event log inline editing is good for post-game review
  • Shift+Space shortcut for clock is excellent
  • Save indicator + dirty dot pattern is clear
  • Phase colour coding is consistent

Option C – Integrated Bar (Most radical change)

Best suited for full-screen dedicated coding sessions.

4 – Option Comparison

A – NLE Standard Recommended

Icon rail + code window centre + right analytics panel + full-width bottom panel. Most familiar to anyone who has used Premiere Pro or DaVinci Resolve. Balances all use cases.

  • Icon rail saves ~200 px vs current sidebar
  • All elements always reachable
  • Natural upgrade path from current layout
  • Right panel collapsible for live mode

B – Code-First

Maximises the button grid. Right column shows live event log + active phase. Analytics behind a tab. Good for operators who only review analytics after the game.

  • Largest possible button targets
  • Active phase most prominent
  • Less screen split — simpler visually
  • Analytics less accessible during live coding

C – Integrated Bar

No sidebar, full-width toolbar, maximum button grid. Most radical change. Best for dedicated coding sessions on large screens or external displays.

  • Maximum button area
  • Match switching requires an extra click
  • Most disruptive to implement
  • Very clean during live coding
Recommendation: Implement Option A as the primary layout. The icon rail is a straightforward replacement for the full sidebar. The right analytics panel can be toggled. The title bar integration of clock + active-phase removes the need for a separate top bar section. This is the closest to the Premiere Pro model while maintaining all current navigation.

6 – NLE-Inspired Time-Based Features

Since the app handles time-coded events (like an NLE handles time-coded clips), the following features would be natural additions – at whatever priority suits the roadmap:

FeatureNLE equivalentDescription
Playhead scrubbing Playhead drag in timeline Click and drag the white playhead in the timeline to jump the clock to any point; existing jumpToTime API already supports this.
Inline event editing from timeline Double-click a clip to open in source monitor Double-click a phase bar in the timeline → opens an inline row edit popover (adjust start time, end time, phase code, context labels, termination).
In/Out point markers In/Out trim handles Drag left/right edges of a phase bar in the timeline to adjust startTimeMs / endTimeMs post-game.
Review flag markers Markers / chapter points Yellow diamond markers on the timeline ruler for phases flagged needsReview = true; clicking jumps the clock to that time.
Zoom-to-fit Fit-to-window zoom A "fit" button scales the timeline zoom so all recorded phases fit within the visible timeline width.
Keyboard jog J/K/L shuttle keys J = skip back, K = pause, L = skip forward (already partially implemented with skip controls; bind to J/K/L).
Undo history panel History panel Show the last N actions in a collapsible panel (currently only single-step undo exists).

7 – Suggested Implementation Order

  1. Title bar integration – Move clock, active-phase pill, and transport controls into the title bar. Integrate match name as a read-only string with edit-on-click. Remove the standalone top bar and match details card from the code window. (Highest impact, minimal risk.)
  2. Icon rail – Replace the 240 px sidebar with a 40 px icon rail during coding sessions. Nav can still expand on hover/toggle if needed. (Frees ~200 px of horizontal space immediately.)
  3. Remove code window width constraint – Change the 720 px w-[720px] to flex-1 so the button grid fills available space.
  4. Analytics panel toggle – Add a collapse/expand button to the right analytics panel with persistent state (localStorage).
  5. Bottom panel tabs – Consolidate Log and Timeline as tabs in the bottom panel. Move "Analytics" as a third tab if the right panel is collapsed.
  6. Progressive disclosure polish – Apply the specific items from Section 2 above (jump-to-time, phase context columns, etc.).
  7. Draggable panel borders – Add drag handles to the left edge of the analytics panel and the top edge of the bottom panel (resize handles already exist for the event log height).
  8. NLE time features – Playhead scrubbing, inline timeline editing, review markers (lower priority, higher effort).
